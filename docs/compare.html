Jig, OpenSpec and Spec Kit

Three spec-driven tools, three different questions

Dustin Diaz
October 2026 · Checked against OpenSpec v1.14.1 and Spec Kit v1.1.3

All three tools agree on the big idea: decide what to build, in writing, before an agent writes code. They differ on who that writing is for and how far past the spec they go.

OpenSpec is built around one change at a time, and keeps a living spec for each area of the codebase. Spec Kit is built around a feature's spec, plan and tasks, and works with almost any coding agent. Jig is built around a team: product requirements and sign-off on one end, parallel agents, review and a postmortem on the other.

This page is written by the Jig team, so read it with that in mind. We've tried to be fair, and we say where the others are ahead. If something here is wrong or out of date, open an issue.

Which one fits

Choose OpenSpec if you mostly change existing code and want something light. Its change folders are easy to review, and archiving each change into a living spec per area means the specs describe the system as it is now, not as it was planned. That's an idea we plan to borrow.

Choose Spec Kit if you want a thorough, well-documented process that works with whichever coding agent each developer prefers. Its constitution, checklists and cross-artifact analysis catch a lot before implementation starts, and its extensions cover bug fixing and idea assessment.

Choose Jig if you're a team where:

  • product, design or other stakeholders need to read the requirements and sign off;
  • work is tracked in Linear, Jira or GitHub Issues;
  • several agents build in parallel and you want every task checked against the spec;
  • you want review, pull request responses and a postmortem that improves the next run, in the same pipeline.

Where Jig is behind

  • Agent support. Jig is built for Claude Code. Gemini CLI and Codex have adapters, but the live PRD page needs Claude. Spec Kit and OpenSpec support far more agents.
  • Living specs. OpenSpec keeps per-area specs current as changes land. Jig keeps each PRD current while its work moves, but doesn't yet merge shipped specs into a per-area record.
  • Weight. A full Jig pipeline is more process than a quick fix needs. Work type sets the depth (a bug skips the PRD and gets a lighter review), but OpenSpec is lighter still.
  • Community. OpenSpec and Spec Kit have tens of thousands of users and many contributors. Jig is newer and smaller.

Checked on October 10, 2026 against each project's own repository and documentation: OpenSpec v1.14.1, Spec Kit v1.1.3 and its docs. Both projects move quickly.
